Terminal KPIs that show their denominator.

On-time rate, dwell time and arrival status for logistics dashboards, in about 100 lines of dependency-free JavaScript. Missing timestamps are counted and excluded, never silently treated as on time. Bad input throws instead of producing a confident wrong number.

example.mjs
import { onTimeRate }
  from '@phlppgdfry/logistics-kpi-utils';

onTimeRate([
  { id: 'call-1', planned: '2026-10-12T08:00:00Z',
                  actual:  '2026-10-12T08:04:00Z' },
  { id: 'call-2', planned: '2026-10-12T09:00:00Z',
                  actual:  null },
], { toleranceMinutes: 5 });

// → { total: 2, evaluated: 1, excluded: 1,
//     onTime: 1, late: 0, rate: 1 }
// call-2 has no actual time: excluded and counted,
// not quietly scored as on time.

Why it exists

A 96% on-time rate means nothing if you don't know what was left out.

Without it

Dashboards divide by whatever rows happen to be there. A truck that never arrived drops out of the maths, timestamps without a timezone shift by an hour, and the same visit counted twice inflates the average. The number looks precise and is wrong.

With it

Every function returns its denominator: how many records were evaluated, how many were excluded and why. Timezone-less strings, impossible dates, negative dwell and duplicate IDs are rejected. Status is computed against an explicit scenario clock, never the system time.

How it works
Five functions, each with a written rule for edge cases

  
  
01
dwellHours / delayMinutes
Elapsed hours and signed minutes in UTC milliseconds, so DST and offsets are handled. Negative dwell throws.
02
onTimeRate
Arrivals at or before planned + tolerance, divided by evaluable arrivals only. No denominator gives null, not 0% or 100%.
03
summarizeArrivalStatus
Completed, pending, overdue or unscheduled at an explicit asOf. Future actual timestamps are flagged and never counted as done.
04
summarizeDwell
Mean, median, p95, min and max over closed visits. Percentiles use linear interpolation (R-7), documented and tested.

  
How one record is judged
01
Validateunique non-empty id, ISO time with explicit offset
02
Classifyagainst the scenario clock: completed, pending, overdue, unscheduled
03
Exclude & countmissing values leave the denominator but stay visible
04
Aggregaterate or statistics over evaluable records only
05
Return evidenceresult plus total, evaluated and excluded
